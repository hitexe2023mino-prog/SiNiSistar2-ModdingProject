# SPEC004 テストシナリオ（実機）

正本: [`docs/specifications/SPEC004.md`](../specifications/SPEC004.md) v1.2。自動テストで判定できない受け入れ条件（AC-301〜AC-321）と付録Aの実測手順を記載する。

## 検証の基本装備

判定材料は **HUD**（5.8）と **デバッグ操作**（5.9）である。ログ（`[intervention]` 行）は事後の証跡として併用する。

| 操作 | 既定キー |
|---|---|
| HUD循環（`Off` → `Compact` → `Full`） | `F5` |
| デバッグ操作パネル開閉 | `F6` |

パネルを開いた状態で数字キーが各操作に対応する。パネル自身が一覧を表示するため、本書で番号を暗記する必要はない。

**検証用の設定**（`BepInEx/config/community.sinisistar2.spawn.cfg`）:

```
[Debug]
HudMode = Full
DebugCommandsEnabled = true
```

`DebugCommandsEnabled` を有効にしない限り、パネルは状態表示のみで操作は一切実行されない（FR-331）。

**デバッグ操作の性質**: 短絡されるのは**待ち時間と確率だけ**である。上限、除外エリア、拘束中・イベント中の禁止、出現位置の条件は通常どおり効く（FR-332）。強制しても何も起きない場合、HUDとログがその理由を示す。これは不具合ではなく仕様である。

共通準備:

1. `dotnet build .\SiNiSistar2.Edi.sln -c Release` でプラグインが `BepInEx/plugins/community.sinisistar2.spawn/` に配置されていることを確認する。
2. 初回起動で設定ファイルが生成される。以後は編集して再起動する。
3. セーブ比較を行うシナリオでは、開始前にセーブデータをバックアップする。

## S-0: HUDとパネルの成立（AC-317, AC-319, FR-329）

1. `HudMode = Off` で起動し、通常プレイで何も描画されないことを確認する。
2. `F5` を押すたびに `Off` → `Compact` → `Full` → `Off` と循環することを確認する（AC-317）。
3. `F6` でパネルが開き、コマンド一覧が表示されることを確認する。
4. `DebugCommandsEnabled = false` の状態で数字キーを押し、**何も起こらない**こと、パネルに有効化方法が表示されていることを確認する（AC-319 前段）。
5. HUD表示中にゲームのUI（メニュー、ステータス、拘束ゲージ）が通常どおり動作することを確認する（FR-328）。SPEC003 の快楽オーバーレイと同時表示しても互いに壊れないこと。

以降のシナリオは `HudMode = Full`、`DebugCommandsEnabled = true` を前提とする。

## S-1: 既定設定の健全性（AC-310, AC-312）

1. 既定設定のまま起動し、任意のエリアを移動する。
2. 確認: ログに設定エラーがない。HUDの `BOX` 行が `disabled`、ギミック複製の介入ログが出ない（両機構は既定無効）。
3. `SpawnCountMultiplierMin = 0.5` に書き換えて再起動し、エラー提示と既定値での続行（起動失敗しないこと）を確認する（AC-312）。

## S-2: 出現調整の再現性と変化（AC-301, AC-302, AC-309, A-2）

1. `Seed = 12345` を設定し、敵スポナーのあるエリアへ入る。HUDの `TUNING` 行で倍率（平均）と `base Normal/Hard`、`AREA` 行で `visit #` と `seed` を確認する。
2. 同じエリアを出入りし、入場回数が同じになるようにやり直して同じ倍率になることを確認する（AC-301 後段）。
3. **エリア再抽選コマンド**を使うと、シーンを出入りせずに倍率が引き直される。`Seed = 0` にして数回実行し、値が変わり得ることを確認する（AC-301 前段）。
4. HUDの `TUNING` 行の `base` が、SPEC002 有効時に `Hard`、無効時に `Normal` になることを確認する（AC-309）。
5. 出現した敵種がログの `pools=[...]` に含まれることを確認する（AC-302）。
6. **A-2 実測**: `SpawnCountMultiplierMin/Max = 3.0` の極端値で、実際の出現数が増えるかを SPEC002 の有無それぞれで確認し、トレーサビリティへ記録する。

## S-3: 停滞ペナルティ（AC-303, AC-318, A-5）

HUDの `STAY` 行が `dwell <経過>/<しきい値>`、`moved <移動量>/<しきい値>`、`next <残り秒>` を表示する。

1. スポナーのあるエリアで立ち止まり、`dwell` が増え `next` が減っていくことを確認する。
2. `next` が 0 に達した瞬間に追加出現が発生し、`ADD` 行の消費数が増えることを確認する（AC-318）。**設定の90秒を待つ必要はない**: 停滞早送りコマンドで成立直前まで進められる。
3. 移動を再開すると `STAY` 行が `moving` へ戻り、`dwell` が 0 から数え直しになることを確認する（AC-303）。
4. 拘束中・イベント中に `STAY` 行が `measurement paused (hold / event)` になり、`dwell` が進まないことを確認する（FR-311）。
5. **A-5 実測**: 画面外に出現した敵が接近で活性化するかを観察して記録する。

## S-4: 奇襲（AC-304）

1. **奇襲強制コマンド**を実行し、`ADD` 行の `last:` が `(offscreen+behind)` になること、出現位置がプレイヤーの向きと反対側であることを確認する。
2. **追加出現強制コマンド**では `(offscreen)` になることを確認する。
3. `POINTS` 行の `offscreen N, of which behind M` を見ながら向きを変え、`behind` の数が変化することを確認する。`behind` が 0 のとき奇襲強制が「位置なし」で拒否されることを確認する（FR-307）。

## S-5: 上限（AC-305, AC-320）

1. `AdditionalSpawnCapPerVisit = 2`、`AdditionalAliveCap = 1` にする。
2. 追加出現強制を連打し、`ADD` 行が `1/2 (alive 1/1)` で止まり、`last:` に `cap reached` が出ることを確認する（AC-320）。
3. 出現した敵を倒すと `alive` が減り、再び強制できることを確認する。合計2体で打ち止めになることを確認する（AC-305）。

## S-6: 除外エリア（AC-306, AC-320）

1. ボス戦・チュートリアル・ギャラリー再生の各シーンでHUDが `excluded by default` を表示することを確認する。
2. その状態で追加出現を強制し、`this area is excluded` として拒否されることを確認する（AC-320）。
3. 通常エリアで areas.json に `"<SceneID名>": {"excluded": true}` を書き、HUDが `excluded by areas.json` を表示することを確認する。

## S-7: 巻き戻しと同一性（AC-307, A-8）

1. セーブをバックアップし、全機構有効（極端値可）で1時間程度プレイしてセーブする。
2. プラグインフォルダ `BepInEx/plugins/community.sinisistar2.spawn` を削除して起動し、挙動がMOD導入前と一致することを確認する。
3. セーブデータを比較する。差分が「プレイの進行そのもの」に限られ、MOD固有の残留がないことを確認する（A-8 を兼ねる）。
4. ゲーム中に `Enabled = false` へ変更し、`interventions rolled back` ログと出現パラメータの復元を確認する。HUDが消えることも確認する。

## S-8: EDI・難易度MODとの共存（AC-308, AC-309）

1. SPEC001/SPEC002 のMODと同時に起動する。
2. EDI のトリガーカタログに既存トリガーの欠落がなく、デバイス制御が停止しないことを確認する（SPEC001 のテストシナリオの回帰）。
3. `F5` / `F6` が SPEC003 の `F7`〜`F11` と競合しないことを確認する。競合する構成にした場合は `[Debug]` のキー設定で回避する。
4. HUDの `TUNING` 行の `base Hard` を確認する（AC-309）。

## S-9: 診断モードとミミック保有調査（A-12, FR-318）

1. `DiagnosticsEnabled = true` で各エリアを巡回する。**診断出力コマンド**で任意の時点に書き出せる。
2. `BepInEx/diagnostics/community.sinisistar2.spawn/inventory/<SceneID>.json` に `spawners[].enemies` と `mimicPoolCount` が記録されることを確認する。
3. `mimicPoolCount > 0` のシーン一覧を作り、トレーサビリティの A-12 へ記録する（推定は下水道系）。HUDの `BOX` 行でも `no mimic pool` かどうかが即座に判る。

## S-10: ミミック疑似宝箱（AC-314〜AC-316, AC-321, A-9〜A-11）

前提: S-9 で `mimicPoolCount > 0` のエリアが判明していること。`MimicBoxEnabled = true` を設定する。

1. **A-9 実測**: ミミック保有エリアへ入り、HUDの `BOX` 行に `placed N/M` が出ることを確認する。出ない場合、`EnmID_Mimic` の実装クラスが `OnlyHoldEnemy` でない可能性をトレーサビリティに記録し、`MimicBoxEnabled` を無効へ戻す。
2. ゲーム配置のミミックに接触して通常どおり拘束されること（未登録個体への無介入、FR-324）を確認する。
3. **抽選を当たりに固定**してから疑似宝箱に接触し、バニラの拘束が進行すること、HUDの `PINNED->MIMIC` が消費で消えること、ログに `resolved as mimic (PINNED)` が出ることを確認する（AC-321、FR-321）。
4. **抽選を外れに固定**して接触し、拘束されず報酬が付与されること、ログが `resolved as reward (PINNED)` になることを確認する（A-10）。所持品とMP玉散布を確認する。
5. 固定を使わずに接触し、`(rolled)` と記録されること、`BOX` 行の `mimic` / `reward` の決着数が増えることを確認する（AC-321 後段）。
6. **A-11 実測**: 外れの後にセーブ→ロードし、図鑑・実績・討伐関連・`TemporaryEnemySaver` 由来の敵状態に異常がないことを確認する。`bodyRemoved=False` の縮退が出た場合、個体が無害に残置され再接触でも拘束されないことを確認する。
7. **疑似宝箱配置コマンド**で `MimicBoxesPerVisit` 超の配置が拒否されること、ミミックプールの無いエリアで `this area has no mimic pool` になることを確認する（AC-314）。
8. 当たり・外れの前後で本物の宝箱の開封状態と内容物が変化していないことを確認する（AC-316）。

## S-11: 性能（AC-313）

1. HUD `Off` と `Full` の両方で、スポナーの多いエリアへの入場時にヒッチがないことを確認する。`Full` は出現位置候補の走査を毎秒2回行うため、ここが最も負荷の高い構成である。
2. 停滞計測中の定常フレームでフレームレートの悪化がないことを確認する。
3. 気になる場合は `LogInterventions = false` でも再確認する。

## 結果の記録

各シナリオの結果は `docs/implementation/SPEC004-traceability.md` の該当行（状態列）と付録A現況表を更新して記録する。A-2 / A-9 / A-11 の結果が否定だった場合は、SPEC004 9章の縮退に従い設定を戻したうえで、仕様の改訂（refine-specification）へ引き継ぐ。
