## 撤回1: 宝箱位置シャッフル（v1.0 の 5.5、v1.1 で撤回）

### 撤回した内容

v1.0 の 5.5 は「エリア入場毎に、同一シーン内の宝箱オブジェクト（`TreasureBoxParameter` を持つオブジェクトの root）の位置を相互に入れ替える」機構だった。既定無効の段階導入として次を定めていた。

- 入れ替えは同一シーン内に限る。開封フラグ（`m_TreasureBoxFlag`）・内容物・演出参照はオブジェクトに帯同し書き換えない。
- 宝箱が1個以下のシーンでは無効果。開封済みの宝箱もシャッフル対象。
- 開封演出（カメラ、`m_UITransform`、`m_DropPosition`）の位置追従は実測項目（旧A-6）。

対応していた規範ID: **FR-314**（同一シーン内の位置入れ替え限定とフラグ・内容・演出の不変更）、**AC-311**（帯同の検証）、**DEC-305**（シーン内位置シャッフルのみ・既定無効）、**付録A-6**（演出追従の実測）。

### 撤回の理由

1. **効果がほぼ無い**。対象ビルドの宝箱は全編で約30個（`TreasureBoxFlag` enum は約31値）で、1シーンに複数の宝箱を持つシーンが稀。同一シーン内の入れ替えという進行保護の制約を守る限り、大半のシーンで無効果だった。
2. **未検証リスクだけが残る**。開封演出の位置追従（旧A-6）が破綻した場合、得られる価値に対して検証・縮退のコストが釣り合わない。
3. **上位互換の設計が見つかった**。ゲーム自身が持つミミック（`EnmID_Mimic`。宝箱に擬態し接触で拘束する敵）を疑似宝箱として追加スポーンし、接触時に当たり外れを抽選する方式（v1.1 の新5.5）が、「宝箱の不確実化」という同じ目的を、本物の宝箱・セーブフラグ・進行必須品に一切触れずに満たす。ユーザーは 2026-08-09 に置き換えを決定した。

### 再検討する場合の注意

- 位置シャッフルを再検討するなら、旧A-6（演出追従）に加え、イベントラベル実行系（`TreasureBoxLabel` / `CommonLabelEventBaseAsync`）がトリガー用コライダーと視覚オブジェクトのどちらの Transform を参照するかの実測が必要である。
- シーン横断の移動・内容物シャッフルは、鍵アイテム（`TresureBoxVillageKeyA/B`）と `TreasureType.Relics` の進行破壊、および開封フラグとセーブの対応崩れのため、v1.0 時点から非対象である（SPEC004 4.5 の代替案表を参照）。
