# 変更履歴

このリポジトリが抱える3つのMODの版を記録する。ゲーム同梱の `changelog.txt` は BepInEx のものであり、本書とは無関係である。

版はMOD単位で進む。3つは互いに独立して動作し、片方だけを更新できることが利点だからである（SPEC001 の EDI連動MODとの互換維持は開発の前提でもある）。タグも `<mod>-v<version>` の形でMOD単位に付ける。

## community.sinisistar2.pleasure

### 1.1.0 — 2026-08-09

拘束中の敗北条件の置き換え方を改訂した（SPEC003 v1.1）。v1.0 は「HPが `0` へ達することだけを止める」形で、HPは `1` で停止していた。実プレイでは拘束中もHPが削られ続け、限界到達後の生死はHPの残量が決めていた。切り離しが完了していなかった。

**性的攻撃をHPから切り離した（5.1、FR-203〜206、DEC-256）**

- 拘束中に性的と判定された被弾は、HPを1点も減らさない。抑止するのはHPの減算だけで、被弾の成立・ダメージ表示・被弾演出・状態異常の付与・MPの消費は従来どおり
- 判別は既存の `Sexual` / `NonSexual` / `Auto` をそのまま被弾ごとに使う。`Sexual` の敵は何をしてもHPを削らず、`Auto` の敵は攻撃ごとに分かれる
- **非性的な攻撃、毒などのスリップダメージ、環境ダメージには介入しない。** 拘束中でもHPは尽き得るし、尽きれば絶頂回数と無関係にゲームオーバーになる
- `StatusCondition.RemainHp1Msv` への寄与は撤去した（FR-277）

**絶頂限界の到達をその場の致死にした（5.5、FR-215、FR-216、DEC-257）**

- 絶頂が成立して回数が限界に達した瞬間に、HPの残量を問わずHPを `0` にする。敵の次の一撃を待たない
- ゲームオーバー処理そのものは呼ばない。HPを `0` にするところまでがMODの仕事であり、死亡判定・演出・リトライ・ペナルティはゲームの経路が走る（DEC-209 を維持）
- 発火は絶頂の成立時のみ。毎フレームの判定にすると、限界以上のまま保存したセーブをロードした瞬間に死ぬ（DEC-258）

**設定**

- `Survival.SuppressHp0WhileBound` を廃止し、`Survival.SuppressSexualHpDamage` へ置き換えた。旧キーが残っていれば起動時に1回その旨を記録する
- 既定値がゲームの挙動を変えなくなった。`SuppressSexualHpDamage` は既定で真だが、`PleasureGainPerHit` が `0` の間は抑止も働かない。快楽が上がらないのにHPも減らない状態を作らないためである（FR-278）
- 撤回した `FR-260`（耐える時間の抽選、搾乳の開始キー）ほか、実体を失った要件・判断・実測記録を仕様書から取り除き、[`SPEC003-withdrawn.md`](specifications/SPEC003-withdrawn.md) へ非規範の履歴として分離した

**実機で確定すること**

- A-50 — `BattleMainParameter.DontSub` が減算を止めるか。止めなければ減った分を書き戻す経路へ自動で倒れる
- A-51 — `HP.SubAll` でHPが `0` になり、ゲーム自身の死亡判定が拾うか。効かなければ `SetCurrentValue(0)` → `Lelia.RequestCommonDead` の順に降りる

どちらも効いた手段が `[probe]` 行に出る。

### 1.0.0 — 2026-08-09（タグ `pleasure-v1.0.0`）

SPEC003 の実装がひととおり揃った。仕様書の状態を「実装可能」から「v1.0（実装済み）」へ改める。

**快楽と絶頂（5.2〜5.6）**

- 拘束中の敗北条件をHPから切り離し、快楽ゲージへ置き換えた。HP0の抑止は寄与の登録として行い、ゲームオーバー処理そのものは呼ばない（DEC-209）
- 快楽が上限に達すると絶頂し、回数が耐久度から決まる限界に達すると、抑止を外すことで通常のゲームオーバー経路へ戻す
- 敵ごとに「性的攻撃を行うか」を分類でき、F10 の編集画面で判断を書き換えられる
- 絶頂時に画面端へピンクの靄を描く

**堕落（5.7）**

- 快楽の上昇量に掛かる蓄積軸を **堕落（Corruption）** とした（FR-265）。一方向にのみ増え、いかなる治療でも減らない
- 進行を **淫紋** の意匠で可視化する。作者が用意した6レイヤ（`lust-crest-Lv1.png` … `Lv6.png`）を順に重ね、同期して明滅させる（FR-266、FR-271）
- 堕落が閾値へ達すると、ゲーム自身の `LustMarkCurse` をストック制で付与する。着用中は堕落の獲得が加速する（FR-267）
- 最終ストックで **昇華** し、以後その周回は解呪不可となる。それ未満は解呪可だが、堕落が要求し続ける限り即座に付け直される（FR-273、FR-274）

**膨乳と母乳（5.8）**

- `Breast` の反復適用と母乳ゲージの満量で `BreastSuper` へ遷移させる
- `BreastSuper` の継続時間は母乳ゲージそのものとした。ゲージは常時減り、性的被弾で戻る。搾乳キーは持たない（FR-264、DEC-241）
- 専用の立ち絵を状態異常自身の `PortraitParameter` から適用する（FR-221、DEC-235）

**保存（5.9）**

- 堕落・絶頂回数・膨乳回数・母乳・淫紋の受領をセーブスロット単位のサイドカーへ保存する（schema 5）
- 旧名 `sensitivity` で書かれたサイドカーも読む
- セーブ未読込の状態を新規runの開始とみなし、New Game+ を含めて全ての蓄積を戻す（FR-272、DEC-247）

**撤回した要求**

- FR-257 / FR-258 — 自己搾乳の演出再生。当該演出は暗転・仮想カメラ切替・そのマップ固有の役者一式の点灯で構成されており、アニメーションの再生ではなかった（A-42、DEC-240）
- FR-268 の一部 — 絶頂時のカメラシェイク。`Camera.main` がUI側のカメラであり、揺れたのはボタンだった。正しい経路（Cinemachine Impulse）を採れる目処が立つまで持たない（A-49、DEC-255）

**同梱ツール**

- `scripts/enhance_image.py` — 平面的な図案の高解像度化。Real-ESRGAN（無ければ古典パイプライン）と白背景のアルファ化
- `scripts/pdn_layers.py` — Paint.NET なしで `.pdn` からレイヤを取り出す
- `scripts/crest_preview.py` — 淫紋の段階描画を画面外で確認する
