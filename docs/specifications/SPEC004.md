## 1. 概要

### 1.1 背景と問題

SiNiSistar2 の敵配置は、シーン（エリア）ごとにあらかじめ置かれた `SiNiSistar2.Obj.EnemySpawner` などのスポナーが決める静的なものである。スポナーは出現数・出現間隔・クールタイムに `Hard` 用の上書き値（`m_SpawnCountHard` 等）を持ち、`Hard` 難易度でのみ出現数が増えるが、それ以上の変化はない。周回すると出現は毎回同じで、緊張感が薄れる。

また、エリアに留まり続けても不利がなく、安全地帯で待つ戦術が常に成立する。プレイヤーの背後から敵が現れる状況もゲーム側の演出以外では発生しない。

対象ビルドの調査（付録B）により、次が確認できた。

- エリアは `SceneID` enum で識別され、現在エリアは `MapManager.CurrentSceneID` で取得できる。
- スポナーは重み付きの敵種リスト（`SpawnSetting`: `m_Weight`、`m_EnemyPoolSetting`）、出現位置の集合 `m_SpawnPoints`、位置選択方式 `PositionChoiceType`（`FarFromPlayer` / `Random`）を持つ。
- 敵の実体はプール（`EnemyPool`）で管理され、`EnemyPool.Build` / `Setup` / `TryGet` が interop から呼び出せる。プールが参照する敵プレハブ（`EnemyPoolSetting.m_SpawnEnemy`）はそのシーンに読み込まれた敵に限られるため、**シーンのスポナーが持つプール設定を使う限り「そのエリアに対応した敵」であることが構造的に保証される**。
- シーンセットアップの完了は `ManagerList.HasDoneSceneSetUp` で観測できる（SPEC002 の実装で実証済み）。
- プレイヤーの位置と向きは `ObjectManager.Lelia` の `Position` / `Dir` で、カメラは `CameraManager.MainCamera` で取得でき、画面外判定が可能である。

一方、罠・落下物は汎用の「罠」ファミリーが存在せず、`VillageFallObject` などシーン固有の一点物ギミックの集合である。宝箱は全編で約30個が `TreasureBoxFlag` enum の固有フラグとセーブ状態に1対1で結び付き、進行必須品（`TreasureType.Relics`）を含む。これらへの介入は敵の追加配置と同じ確度では成立しない。

宝箱の不確実化については、ゲーム自身がミミック（`EnemyID.EnmID_Mimic`、宝箱に擬態し接触で拘束を行う敵）を持つことが確認できた。実装クラスの有力候補は `OnlyHoldEnemy`（`m_HoldCollider` への接触で拘束ガチャ `m_GachaBindParameter` を開始する、拘束専用の `EnemyObject` 派生）である。さらに、報酬付与の公開経路として `InventoryHandler.AddItem(ItemID, count)`（所持品への追加）と `DropLootPool.Play(position, …)`（MP玉・レリック玉の散布）が interop から呼び出せる。本物の宝箱へ介入せずに「開けるまで中身が分からない箱」を成立させる材料が、ゲーム側に揃っている。

### 1.2 目的

- エリアをロードするたびに、そのエリアに対応した敵の出現数・構成が変化する状況を作り、難易度と再訪時の緊張感を高める。
- 同一エリアに停滞するプレイヤーへのペナルティとして、画面外から敵を追加出現させる。
- 奇襲として、プレイヤーの背後側の出現位置から敵を追加出現させる。
- 罠・落下物のエリア毎の追加配置と、ミミック疑似宝箱による宝箱の不確実化を、進行破壊を起こさない範囲で段階導入する。
- 調整値を BepInEx 設定で変更可能にし、ゲームのセーブデータとアセットを書き換えない。
- SPEC001/002/003 の各MODと同一ゲームルートで共存する。

### 1.3 成功条件

1. 同一エリアへ入り直したとき、MOD無効時と比べて敵の出現数または構成が変化し得る。変化する敵は当該エリアのスポナーが本来参照する敵種に限られる。
2. 同一エリアに設定時間以上停滞し、かつ移動量が設定値未満のとき、画面外の出現位置から敵が追加出現する。停滞していない間は発生しない。
3. 奇襲が有効なとき、プレイヤーの向きと反対側の出現位置が選ばれ得る。奇襲で出現した敵も通常の敵と同じ経路で活性化・戦闘・消滅する。
4. 追加出現の総量は設定上限で制限され、上限到達後は追加出現しない。
5. MODを取り外し、または全機構を無効化して起動したとき、ゲームの挙動がMOD導入前と一致する。セーブデータにMOD由来の差分が残らない。
6. SPEC001 の EDI連動MODが同時に動作している状態で、既存トリガーの欠落が発生せず、デバイス制御が停止しない。追加出現した敵のトリガーは通常の敵と同様に捕捉される。
7. SPEC002 の難易度MODと同時に動作するとき、`Hard` 上書き解決後の値を基準に増量が適用され、二重増幅の暴走が起きない。
8. MODの介入がフレーム時間を計測可能な範囲以上に悪化させない。
9. （段階導入）罠・落下物の複製が有効化された場合、複製元と同じシーン内でのみ複製され、実測登録済みの型に限られる。
10. （段階導入）ミミック疑似宝箱が有効化された場合、ミミックのプールを持つエリアに疑似宝箱が配置される。疑似宝箱は接触するまで当たり外れが決まらず、当たりはバニラのミミック拘束がそのまま進行し、外れは拘束なしで報酬が付与される。本物の宝箱の挙動・開封フラグ・内容物は一切変化しない。

## 2. スコープ

### 2.1 対象

- BepInEx IL2CPP プラグイン（GUID `community.sinisistar2.spawn`）としての Harmony ランタイムパッチと、シーンセットアップ完了後のランタイム介入。
- エリア（`SceneID`）単位の出現調整プロファイルと乱数シード。
- 既存スポナー（`EnemySpawner`、`SimpleSpawnArea`）の出現数・出現間隔・クールタイム・プール上限へのランダム化倍率の適用（5.2）。
- MOD主導の追加スポーン。画面外条件・背後条件・停滞ペナルティ条件による出現位置の選別（5.3）。
- 同一シーン内に既存するギミックの複製配置。型別の許可リスト制で既定無効（5.4）。
- ミミック疑似宝箱。ミミックのプールを持つエリア限定で、既定無効（5.5）。
- 追加出現量の上限、失敗時の縮退、全介入の巻き戻し。
- 診断出力（エリア毎のスポナー・ギミック・宝箱の在庫調査）。
- 可観測性HUD。本MODの内部状態をゲーム画面上に重ねて表示する読み取り専用の表示（5.8）。
- デバッグ操作。待ち時間と確率に支配された事象を任意の時点で発生させ、実機検証を成立させるホットキー操作（5.9）。

### 2.2 非対象

- そのエリアのシーンに読み込まれていない敵種の出現。アセットバンドル（`AssetBundleLoader`）から敵プレハブを追加ロードする方式は、ロード時間・メモリ・ビルド依存性の代償が大きく採らない（DEC-302）。
- 任意座標への敵出現。接地・到達可能性を保証できないため、出現位置は既存の出現位置集合から選ぶ（DEC-303）。
- ボス戦・イベント戦・ギャラリーシーンへの介入（DEC-310）。
- 敵のAI、行動パターン、ステータス、ドロップの変更。ミミック疑似宝箱の「当たり」個体への介入もこれに含む（拘束はバニラのまま進行させる）。
- 本物の宝箱への一切の介入。位置移動、内容物（`m_ItemID` / `m_Relics`）の変更、`TreasureBoxFlag` の書き換えを行わない。宝箱位置シャッフルは v1.0 で計画したが撤回した（撤回記録参照）。
- ミミックプレハブの外部供給（ギャラリーシーン `Ga_Mimic` やアセットバンドルからのロード）。ミミックのプールが無いエリアへの疑似宝箱の配置はこれに依存するため、延期事項とする（14.2）。
- 新規ギミック・新規罠プレハブの作成。複製はシーン内の既存インスタンスに限る。
- `GameAssembly.dll`、`global-metadata.dat`、ゲームアセット、セーブデータファイルの書き換え。
- ゲーム内で設定値を編集するUI。設定は BepInEx 設定ファイルで行う。HUD（5.8）は読み取り専用であり、設定を書き換えない。
- HUDによるゲーム自身のUI階層への介入。描画は IMGUI のオーバーレイに限り、ゲームの Canvas・UI オブジェクト・`Time.timeScale` に触れない（DEC-315）。
- デバッグ操作による安全上限の回避。5.9 の操作は待ち時間と確率だけを短絡し、上限（FR-308）と除外（FR-311）を迂回しない（DEC-316）。

### 2.3 前提と制約

- MODはBepInEx 6 IL2CPP環境で動作し、`0Harmony.dll` と `Il2CppInterop.HarmonySupport.dll` を利用できる。
- 介入はすべて実行時に行う。ゲームバイナリとアセットを改変しない。SPEC001 の EDI連動MODが `GameAssembly.dll` と `global-metadata.dat` の SHA-256 を照合するため、これは共存の必須条件である。
- 対象ビルドの IL2CPP ネイティブ実装は interop アセンブリから読めない。本仕様が参照するシンボルは実在するが、**その意味論の一部は推論である**。推論に依存する項目は付録Aに列挙し、実装中の実測で確認する。実測が推論を否定した場合、当該機構は縮退動作（9章）に従う。
- スポナーの出現処理は UniTask によるメインスレッド上の非同期処理である。MODの介入もメインスレッド上で完結させる。
- 敵はプール（`EnemyPool.PoolingArray`）で管理され、プール容量（`EnemyPoolSetting.m_MaxSpawn` / `m_MaxSpawnHard`）が同時存在数の上限を規定する。容量を超える追加出現は成立しない。
- SPEC002 が有効な場合、難易度の報告値は `Hard` になり、スポナーの `*Hard` 系上書きと `HardOnly` 配置が既に有効である。本MODの増量はその解決後の値を基準にする（DEC-309）。
- ユーザーは、追加出現の結果として難所化・脱出不能な状況が生じ得ることを許容する。ただし進行不能（イベント・ボス・宝箱の破壊）を生んではならない。

## 3. 用語

| 用語 | 定義 |
|---|---|
| エリア | `SceneID` で識別されるゲームシーン。`MapManager.CurrentSceneID` が現在エリアを示す。 |
| スポナー | シーンに配置された敵出現装置。`EnemySpawner` と `SimpleSpawnArea` を指す。 |
| プール | `EnemyPool`。敵プレハブ（`EnemyPoolSetting.m_SpawnEnemy`）から生成した実体を再利用する機構。 |
| 基準値 | ゲームが `Hard` 上書き解決後に採用する出現数・間隔・クールタイム・プール上限の値。MODの倍率はこの値に乗じる。 |
| 出現調整 | 既存スポナーのフィールドを基準値×倍率へ書き換える介入（5.2）。 |
| 追加スポーン | MODがプールから敵を取得して出現させる介入（5.3）。 |
| 出現位置集合 | 当該スポナーの `m_SpawnPoints`（`SimpleSpawnArea` は `m_SpawnPoint`）に列挙された Transform の集合。 |
| 画面外 | `CameraManager.MainCamera` のビューポートの外側に位置すること。 |
| 背後 | `Lelia.Dir`（プレイヤーの向き）と反対側に位置すること。 |
| 停滞 | 同一エリアに `StagnationSeconds` 以上滞在し、かつ直近 `StagnationWindowSeconds` 間の移動距離が `StagnationMoveEpsilon` 未満である状態。 |
| ギミック複製 | 同一シーン内に既存する罠・落下物オブジェクトを `UnityEngine.Object.Instantiate` で複製する介入（5.4）。 |
| ミミック | `EnemyID.EnmID_Mimic` の敵。宝箱に擬態し、接触で拘束を開始する。 |
| ミミック疑似宝箱 | MODが追加スポーンしたミミック個体。接触時の抽選で「当たり」か「外れ」かが決まる（5.5）。 |
| 当たり | 抽選の結果、疑似宝箱がミミックとして振る舞うこと。バニラの拘束がそのまま進行する。 |
| 外れ | 抽選の結果、疑似宝箱がただの宝箱だったことになること。拘束は発生せず、報酬が付与される。 |
| 報酬テーブル | 外れ時に付与する `ItemID` と個数と重みの設定リスト（6章 `RewardTable`）。 |
| エリアプロファイル | エリア毎の倍率・確率・上限・許可リストを定める設定の単位（6章）。 |
| 巻き戻し | MODが行った全ての介入を解除し、ゲームをMOD無効時と同一の状態へ戻す操作。 |
| HUD | 本MODの内部状態をゲーム画面上へ重ねて表示する読み取り専用の表示（5.8）。`Off` / `Compact` / `Full` の3表示段階を持つ。 |
| デバッグ操作 | 待ち時間と確率に支配された事象を任意の時点で発生させる操作（5.9）。設定で明示的に有効化した場合にだけ利用できる。 |
| 抽選固定 | 次に成立するミミック疑似宝箱の抽選結果を、確率によらず当たりまたは外れへ固定するデバッグ操作（5.9）。 |

## 4. 採用設計

### 4.1 全体構成

```
BepInEx (IL2CPP)
  └ community.sinisistar2.spawn             ← 本MOD
      ├ SpawnPlugin (BasePlugin)             設定読込、Harmonyパッチ適用、巻き戻し
      ├ SpawnObserver (MonoBehaviour)        シーンセットアップ検知、停滞計測、追加スポーン駆動、HUD描画
      ├ SpawnHud                             IMGUI描画とホットキー処理（5.8）
      ├ SpawnDebugCommands                   デバッグ操作の実行（5.9）
      ├ Harmonyパッチ群                      スポナーのセットアップ介入点（Plugin側のみ）
      └ SiNiSistar2.Spawn.Core               純粋ロジック（ゲーム参照なし・単体テスト対象）
          ├ SpawnProfile                     設定の検証済み表現（エリアプロファイル解決）
          ├ RandomSource                     シード付き乱数（SPEC002 と同型）
          ├ SpawnBudget                      追加出現量の上限管理
          ├ StagnationDetector               停滞判定（位置サンプルから判定のみを行う）
          ├ SpawnPointClassifier             出現位置の画面外・背後の分類（幾何計算のみ）
          └ HudModel                         HUDの表示内容の組み立て（文字列生成のみ）
```

観測と判断（Core）を、ゲームへの読み書き（Plugin）から分離する。Core はゲーム型を参照せず、位置・向き・時刻などの値だけを受け取り判定を返す。この構成は SPEC002/003 と同一である。

### 4.2 エリアと「対応した敵」の解決方法

「エリアに対応した敵」を敵種リストとして設定に書く方式は採らない。エリアのシーンに配置済みのスポナーとそのプール設定だけを出現源とすることで、次を構造的に保証する（DEC-302）。

- 出現する敵は、開発元がそのエリアに置いた敵種に限られる。
- 敵プレハブ・アニメーション・SEなどの依存アセットは必ずロード済みである。
- `HardOnly` 配置を含め、ゲーム側の出現条件の意味論を破壊しない。

エリアプロファイルは「どの敵を出すか」ではなく「どれだけ出すか・どこから出すか」だけを定める。

### 4.3 3つの機構と確度

| 機構 | 節 | 確度 | 既定 |
|---|---|---|---|
| 出現調整（既存スポナーの倍率） | 5.2 | 高。書き換えるフィールドはゲーム自身が `Hard` 上書きで書き換えているものと同じ | 有効 |
| 追加スポーン（画面外・背後・停滞） | 5.3 | 中。`EnemyPool.TryGet` の意味論が推論（付録A） | 有効（保守的な既定値） |
| ギミック複製・ミミック疑似宝箱 | 5.4 / 5.5 | 低。ギミックは型毎の意味論が、疑似宝箱はミミックの実装クラス対応と拘束抑止点が未検証（付録A） | **無効**（5.4 は許可リスト登録制、5.5 は設定で明示有効化） |

確度の低い機構を既定無効で持つのは、要件（罠・宝箱）を仕様から落とさずに、進行破壊のリスクを有効化の明示操作の内側に閉じ込めるためである（DEC-304、DEC-305）。

### 4.4 介入の可逆性

- 出現調整は、スポナー毎に元の値を退避してから書き換え、シーン遷移時・無効化時・アンロード時に復元する。ただしスポナーはシーンオブジェクトであり、シーン破棄と同時に消える。復元は「同一シーン滞在中の無効化」の場合にだけ意味を持つ。
- 追加スポーンで出現した敵はゲームのプールへ返る通常の経路（死亡・消滅）に任せ、MODは所有権を持たない。シーン遷移時に生存していた追加敵はシーンと共に破棄される。
- ギミック複製とミミック疑似宝箱はシーン内限定の操作であり、シーン破棄で消える。セーブデータへ書かれる状態（宝箱の開封フラグ、`TemporaryEnemySaver` の敵状態、討伐・図鑑系フラグ）に影響しないことを付録Aで実測確認する。外れ時の報酬付与（所持品の増加）だけは意図した永続効果であり、ゲーム自身の在庫経路（`InventoryHandler.AddItem`）を通す。
- セーブデータ・アセット・設定ファイル（ゲーム側）には一切書き込まない。

### 4.5 代替案とトレードオフ

| 代替案 | 不採用理由 |
|---|---|
| アセットバンドルから任意の敵をロードして出現 | エリア外の敵が出現し「エリア対応」の要件と矛盾。ロード時間・メモリ・ビルド依存の代償が大きい。 |
| ~~スポナーを介さず `UnityEngine.Object.Instantiate` で敵プレハブを直接複製~~ | **v1.5 で採用へ転じた。** 当初は「プール外の敵は `IsMadeInPool` / `PoolIndex` を持たず、死亡・消滅・カウントの経路が保証されない」として却下したが、実機で通常エリアにスポナーが存在しないことが判明し（A-15）、却下の前提だった「プールという代替がある」が成立しなかった。保証されない経路は付録A A-16／A-17 の実測項目として引き受ける |
| 出現数をゲームの `Hard` 上書きフィールド（`m_SpawnCountHard` 等）へ書く | SPEC002 無効時（報告値が `Hard` でないとき）に読まれない。基準値と倍率の関係も不明瞭になる。 |
| 任意座標スポーン＋`Teleport(trans, isFitGround)` による接地補正 | `isFitGround` の意味論が未検証で、失敗時に空中・壁内出現の危険。出現位置集合からの選別で十分。 |
| 宝箱の内容物（`m_ItemID`）のシーン横断シャッフル | 鍵・Relics が移動すると進行破壊。開封フラグと内容の対応もセーブ互換を失う。 |
| 宝箱の位置シャッフル（v1.0 の旧5.5） | 宝箱は全編で約30個しかなく、複数の箱を持つシーンが稀で効果が薄い。開封演出の追従も未検証だった。ミミック疑似宝箱が同じ目的（宝箱の不確実化）をより高い価値で満たすため撤回（撤回記録参照）。 |
| 疑似宝箱を本物の宝箱オブジェクトの複製で作る | 複製にイベントラベルと `TreasureBoxFlag` の配線が付いてくるため、開封が本物のフラグ・アイテムに波及する。配線の除去はラベル実行系の意味論に依存し確度が低い。ミミック実体方式なら本物の宝箱に一切触れない。 |
| 抽選をスポーン時に確定させる | 接触時抽選と見た目は同じだが、「インタラクトするまで確定しない」という要件の表現として弱く、セーブ・リロードで結果が固定される。接触時抽選なら状態を持たない。 |

## 5. 制御仕様

### 5.1 エリア識別と適用タイミング

1. `SpawnObserver` は毎フレーム `ManagerList.HasCompletedFirstInitialize` と `ManagerList.HasDoneSceneSetUp` を確認し、両者が成立した最初のフレームで「エリア入場」を検知する（SPEC002 実証済みパターン）。
2. 入場検知時に `MapManager.CurrentSceneID` を読み、エリアプロファイルを解決する。プロファイルが無いエリアは既定プロファイルを使う。`ExcludedScenes` に含まれるエリアでは何もしない。
3. 乱数はエリア入場毎に初期化する。`Seed` が `0` 以外なら `Seed ^ (int)SceneID ^ 入場回数` を種とし、`0` なら非決定とする。
4. シーン内の全 `EnemySpawner` / `SimpleSpawnArea` を列挙し、5.2 を適用する。5.3 の駆動を開始する。5.4 / 5.5 は有効時のみ適用する。
5. `ObjectManager.IsCinematicEvent` が真の間、および `MapManager.CurrentSceneID` が `ExcludedScenes` 既定集合（ボス・イベント・ギャラリー・チュートリアル系）に該当する間は、5.3 の追加スポーンを行わない（DEC-310）。

### 5.2 出現調整（既存スポナーのランダム化倍率）

対象フィールドと倍率設定の対応は次のとおり。倍率は基準値（`Hard` 上書き解決後にゲームが採用する値。付録A-2）に乗じ、結果を型の値域へ丸める。

| スポナー側 | 倍率（エリアプロファイル） | 方向 |
|---|---|---|
| `EnemySpawner.m_SpawnCount` | `SpawnCountMultiplier` | 増やす（≥1.0） |
| `EnemySpawner.m_SpawnInterval` | `SpawnIntervalMultiplier` | 縮める（≤1.0） |
| `EnemySpawner.m_CoolTime` / `m_CoolTimeFirst` | `CoolTimeMultiplier` | 縮める（≤1.0） |
| `EnemyPoolSetting.m_MaxSpawn` | `MaxSpawnMultiplier` | 増やす（≥1.0） |

- 倍率はエリア入場毎に `[Min, Max]` の一様乱数から決定する。スポナー毎に独立に引く。これが「ランダム出現」の第一の実現手段である。
- `m_SpawnCountHasHardModeOverride` 等の `*HasHardModeOverride` フラグと `*Hard` フィールドは読み取りのみとし、書き換えない。
- `EnemyPoolSetting.m_MaxSpawn` の書き換えがプール容量へ反映される時点は未検証である（付録A-3）。反映されない場合、出現数の実効上限は元の容量に留まり、これは安全側の縮退である。
- 書き換え前の値をスポナー毎に退避し、同一シーン滞在中の無効化・巻き戻しで復元する。

### 5.3 追加スポーン（画面外・背後・停滞ペナルティ）

**出現源**

実機調査（付録A A-15）により、本作の通常エリアは `EnemySpawner` を用いず、`EnemyObject` の実体をシーンへ直接配置していることが確定した。したがって出現源は次の優先順で解決する。

1. 当該シーンにスポナーとそのプールが存在する場合、プール（`SpawnSetting.m_EnemyPoolSetting` の重み付き抽選）から `EnemyPool.TryGet` で取得する。
2. 存在しない場合、**当該シーンに実在する `EnemyObject` を複製する**。複製元はそのエリアに作者が配置した敵そのものであり、「エリアに対応した敵」であることは 4.2 と同じ根拠で保証される（DEC-302 改訂）。

複製の単位は、複製元の `EnemyObject` を含む最上位の祖先であって、その配下に他の `EnemyObject` を含まないものとする。コンポーネント単体のオブジェクトを複製すると、敵の構成物（当たり判定、演出、AI）が欠ける。

**出現位置**

出現位置は次の順で解決する。いずれも作者が配置した座標であり、MODが座標を発明しない原則（DEC-303）は維持する。

1. スポナーがある場合はその出現位置集合。
2. ない場合は、当該シーンに実在する `EnemyObject` の位置の集合。

**複製の制約**

- 複製した個体は追加出現の上限（FR-308）に数える。
- 複製した個体は、ゲームの敵状態保存（`TemporaryEnemySaver`、`m_Path` を鍵とする）で複製元と衝突してはならない。MODは複製直後にオブジェクト名を変更し、階層パスを複製元と異ならせる。衝突の有無は付録A A-16 で実測する。
- 巻き戻し時、MODが複製した個体のうち生存しているものを除去する。

`TryGet` の意味論（活性化のタイミング、位置設定の正しい手順）は付録A-1 の実測で確定する。

**共通規則**

- 追加スポーンの1エリア滞在中の総数は `AdditionalSpawnCapPerVisit` を超えない。同時生存数は `AdditionalAliveCap` を超えない（`EnemySpawner.AliveEnemyObjectList` とプールの `UsingCount` で計数する）。
- プールが空（`TryGet` 失敗・容量上限）なら追加スポーンは静かにスキップする。強制生成しない。
- 出現位置は当該スポナーの出現位置集合から条件で選別する。条件を満たす位置が無い場合はスキップする（任意座標を発明しない。DEC-303）。
- 追加スポーンした敵に印は付けない。ゲームから見て通常の敵と区別が付かないことを共存の前提とする（7章）。

**画面外条件**: 出現位置のワールド座標を `CameraManager.MainCamera.WorldToViewportPoint` で変換し、ビューポート `[0,1]²` の外側（マージン `OffscreenMargin` を加味）にある位置だけを候補とする。

**背後条件**: `ObjectManager.Lelia` の `Position` と `Dir` を読み、プレイヤーの向きと反対側にある位置だけを候補とする。`AmbushChance` の確率で、通常の追加スポーンの位置選別を背後条件に置き換える。

**停滞ペナルティ**: `StagnationDetector` が停滞（3章の定義）を検知したとき、`StagnationPenaltyInterval` 毎に1体、画面外条件で追加スポーンする。プレイヤーが移動を再開（移動距離が `StagnationMoveEpsilon` を超過）したら停滞状態を解除し、計測を初期化する。拘束中・イベント中（`IsCinematicEvent`）・ゲームオーバー処理中は停滞計測を一時停止する。

### 5.4 罠・落下物の追加配置（段階導入・既定無効）

汎用の罠ファミリーが存在しないため、本機構は**同一シーン内に既存するギミックインスタンスの複製**に限定する。

1. 複製できる型は設定 `AllowedGimmickTypes` に列挙された型名だけである。既定は空集合＝機構全体が無効。
2. 診断モード（6章 `DiagnosticsEnabled`）は、エリア毎に検出したギミック候補（`VillageFallObject` 等、付録Bの候補型）の型名・個数・位置を診断JSONへ出力する。ユーザー（または実装者）はこの在庫を根拠に、実測で複製の成立を確認した型だけを許可リストへ登録する。
3. 複製は元インスタンスの near 位置（`GimmickCloneOffsetRange` 内の乱数オフセット）へ行い、1エリアあたり `GimmickClonesPerVisit` 個を上限とする。
4. 複製直後に例外が発生した場合、当該複製オブジェクトを破棄し、その型をセッション中の拒否リストへ入れて再試行しない。
5. 複製はセーブデータへ状態を書く型（フラグ・カウンタを持つ型）を許可リストへ入れてはならない。診断出力は既知のセーブ連動型（宝箱・イベントレシーバ保持型）に警告を付す。

### 5.5 ミミック疑似宝箱（段階導入・既定無効）

疑似宝箱の実体は、当該シーンのプールから追加スポーンした**本物のミミック個体**である。ミミックは宝箱に擬態する敵であるため、配置された疑似宝箱は接触するまで本物のミミックと視覚的に区別できず、「開けるまで分からない」が構造的に成立する（DEC-311）。

**配置**

1. 有効時（`MimicBoxEnabled`）、エリア入場時にミミック（`EnmID_Mimic`）を含むプール設定が当該シーンに存在するかを確認する。存在しないエリアでは何もしない（供給はシーン内プール限定。DEC-312）。
2. 存在する場合、`MimicBoxesPerVisit` を上限に、5.3 と同じ位置選別（出現位置集合からの選択。画面外条件は課さない）でミミックを追加スポーンする。この個体を疑似宝箱として登録する。
3. 疑似宝箱の生存数は 5.3 の `AdditionalAliveCap` とは別枠で管理する（静止型で戦闘負荷が異なるため）。

**抽選と帰結**

4. 抽選は配置時ではなく、**プレイヤーが接触して拘束が開始される瞬間**に行う（DEC-313）。介入点はミミックの拘束開始処理（候補: `OnlyHoldEnemy.HoldSetup`。付録A-9）への Harmony パッチとし、疑似宝箱として登録された個体だけを対象にする。登録外のミミック（ゲームが元から配置した個体）には介入しない。
5. `MimicChance` の確率で**当たり**: MODは何もしない。バニラの拘束・ガチャ・演出がそのまま進行する。
6. 残りの確率で**外れ**: 拘束の開始を抑止し、当該個体を非死亡経路でプールへ返却（付録A-11）したうえで、報酬を付与する。
   - 報酬テーブル（`RewardTable`）から重み抽選した `ItemID` を `InventoryHandler.AddItem` で所持品へ追加し、介入ログへ記録する。
   - 視覚フィードバックとして `DropLootPool.Play` により少量のMP玉（`RewardLootValue`。`0` で無効）を個体位置に散布する。
7. 抽選の乱数は 5.6 の `RandomSource` から供給する。

**保護**

8. 本物の宝箱（`TreasureBoxParameter` を持つオブジェクト）と、ゲームが元から配置したミミックには一切介入しない。
9. 外れ時の個体除去が「敵を倒した」扱い（討伐フラグ、図鑑、実績、`EnemyDefeatedIDAfterBossBattle` 等）としてセーブへ波及しないことを付録A-11 で実測確認する。非死亡経路が成立しない場合、外れの帰結を「拘束のみ抑止し、個体はその場に残す」へ縮退する（9章）。

### 5.6 乱数と再現性

- 乱数は Core の `RandomSource`（SPEC002 と同型のシード付き実装)に集約する。ゲーム側の `UnityEngine.Random` を消費しない（ゲームの乱数列を変えない）。
- `Seed ≠ 0` のとき、同一エリア・同一入場回数・同一設定での抽選結果は再現する。テストとバランス調整はこの再現性に依存する。

### 5.7 巻き戻し

`Enabled` を無効化したとき、またはプラグインのアンロード時に、次を実行する。

1. 5.2 で書き換えた全スポナーのフィールドを退避値へ復元する（対象シーンが生存している場合）。
2. 5.3 の駆動（停滞計測・追加スポーンのタスク）を停止する。出現済みの敵は回収しない（ゲームの通常経路に任せる）。
3. 5.4 の複製オブジェクトを破棄する。5.5 の疑似宝箱として登録された未接触の個体を非死亡経路で除去し、登録を解消する（拘束が進行中の個体には介入しない）。
4. Harmonyパッチを解除する。

### 5.8 可観測性HUD

本MODの機構は、確率と待ち時間と画面外の事象で構成される。ログだけでは、介入が起きなかったのか、起きたが見えなかったのか、そもそも機構が動いていないのかを、プレイ中に区別できない。HUDはこの区別を与えるために存在する（DEC-314）。

**表示段階**

`Off` / `Compact` / `Full` の3段階を持ち、ホットキーで循環する。既定は `Off` で、通常のプレイでは何も描画しない。

- `Compact`: 1行。エリア名、追加出現の消費数と上限、停滞の進捗、疑似宝箱の残数。
- `Full`: 次の区画をすべて表示する。
  1. **エリア**: `SceneID` 名、入場回数、除外の有無とその理由（既定除外／areas.json）、乱数の種別（シード／非決定）。
  2. **出現調整**: この入場で引いた倍率4種と、基準値が `Hard` 解決後かどうか（AC-309 の判定材料）。調整したスポナー数。
  3. **停滞**: 滞在時間、直近窓の移動距離としきい値、停滞の成立可否、次のペナルティまでの残り秒数。計測が一時停止している場合はその理由（拘束中／イベント中）。
  4. **追加出現**: 消費数と上限、同時生存数と上限、直近の出現の条件（画面外／画面外+背後）と敵種、直近の失敗理由。
  5. **疑似宝箱**: 配置数、未接触数、当たり／外れの決着数、抽選固定の有無。ミミックのプールが無いエリアではその旨。
  6. **候補位置**: 現在の出現位置集合のうち、画面外条件を満たす数と背後条件を満たす数。0 のときは追加出現が起きない理由が位置不足であることが判る。

**配置**

HUDは画面の**右上**へ描画する。左上にはプレイヤーの立ち絵とゲーム自身のステータス表示があり、そこへ重ねると観測対象そのものを隠すことになる。

**制約**

- HUDは読み取り専用である。表示のためにゲームの状態を書き換えず、設定値も変更しない。
- 描画は IMGUI のオーバーレイに限る。ゲームの Canvas、UIオブジェクト、`Time.timeScale` に触れない（DEC-315）。SPEC003 の快楽オーバーレイおよび SPEC002 の拘束ゲージ着色と描画対象が重ならない。
- 描画で例外が発生した場合、HUDを停止し、1回だけ提示する。ゲームの進行と本MODの機構は継続する。
- HUDの状態はセーブデータへ保存しない。設定ファイルにも書き戻さない。

### 5.9 デバッグ操作（既定無効）

5.3 の停滞ペナルティは既定で90秒の滞在を要し、5.5 の抽選は確率事象である。実機で受け入れ条件と付録Aを検証するには、これらを任意の時点で発生させる必要がある。デバッグ操作はそのための短絡である（DEC-316）。

`DebugCommandsEnabled` が有効なときにだけ利用でき、既定は無効である。無効時、操作パネルは状態の表示のみを行い、いかなる操作も受け付けない。

無効時にキーを押しても何も起きないだけでは、機能が壊れているのか無効なのかを利用者が区別できない。操作パネルは、無効である事実、有効化する設定キーとファイル名、および有効化の反映方法を提示しなければならない。無効時にキーが押された場合は、その押下が無視されたことを提示する（FR-334）。

**操作方法**

操作パネルは各操作をボタンとして描画し、マウスのクリックで実行できる。キーボードの数字キーは同じ操作への近道として併存する。一覧を読んでキーを対応付ける作業はパネル自身が担うべきであり、押下が登録されたかどうかを利用者が推測する状態を作らない（DEC-319）。

ボタン操作にはマウスカーソルが必要である。MODは操作パネルが開いている間に限りカーソルの表示とロック解除を保証し、閉じたときに元の値へ戻す。これはHUDが書き換えるゲーム状態の唯一の例外であり、FR-327 の対象外とする。

**有効・無効の切り替え**

有効・無効はパネル上のスイッチボタンで切り替える。ボタンは現在の状態とクリック時の結果を表示し、押下で `DebugCommandsEnabled` を書き換えて設定ファイルへ永続化する。設定が操作を門番することは変わらず（FR-331）、変わるのは門を開ける場所だけである（DEC-318）。

キーボードの切り替えキーは**有効化のみ**を行い、無効化してはならない。操作が正当な理由で何も起こさなかったとき（出現位置なし、上限到達）、利用者が次に取る行動は有効化キーの再押下であり、それが無効化になる設計は、道具を動かそうとしている当人の手で道具を止める（DEC-320）。無効化はスイッチボタンからのみ行う。

設定ファイルは、操作パネルを開いた時点でも読み直す。読み直しの対象は `DebugCommandsEnabled` と `Enabled` に限り、他の設定値は起動時に確定する（DEC-317）。

| 操作 | 効果 |
|---|---|
| 追加出現を強制 | 停滞の成立を待たずに、画面外条件で追加出現を1回試行する。 |
| 奇襲を強制 | 同上。ただし背後条件を必ず課す。 |
| 疑似宝箱を配置 | ミミック疑似宝箱を1個、その場の候補位置へ追加配置する。 |
| 抽選を当たりに固定 | 次に成立する疑似宝箱の抽選を、確率によらず当たりにする。 |
| 抽選を外れに固定 | 同上。外れにする。 |
| エリアを再抽選 | シーンを再読み込みせずに、出現調整と疑似宝箱の配置をやり直す。倍率の再抽選（AC-301）の確認に使う。 |
| 診断を出力 | 現在のエリアの在庫JSONを即時に書き出す（FR-318）。 |
| 停滞を成立させる | 停滞計測を、成立の直前まで進める。停滞の自然な発火（FR-309）を短時間で観測する。 |

**制約**

- デバッグ操作は**待ち時間と確率だけを短絡する**。上限（FR-308）、除外エリア、拘束中・イベント中の禁止（FR-311）、出現位置の条件（FR-307）は迂回しない。上限に達していれば強制操作も何も起こさず、その理由を提示する。
- 抽選固定は1回で消費し、使用したことを介入ログとHUDへ記録する。固定された結果を自然な抽選と取り違えないためである。
- デバッグ操作による介入は、通常の介入と同じ経路を通る。検証のために別経路を用意しない。そうしなければ検証したものが実装と異なる。
- エリアを再抽選しても、既に出現した敵は回収しない。ゲームの通常経路に任せる。

ホットキーの既定値は、同一ゲームルートに常駐する他MODと重複しない値を選ぶ。重複した場合の調停はゲーム側では行われず、両方の機能が同時に反応する。

対象ビルドのゲーム本体は legacy の `KeyCode` 入力を一切使用しない（すべて Unity InputSystem）ため、競合はMOD間でのみ発生する。既知の占有は次のとおり。

| キー | 使用者 |
|---|---|
| `F6` | SPEC001 EDI連動MOD の `Authoring.OpenGuiKey`（funscript オーサリングGUIを開く） |
| `F7`〜`F11` | SPEC003 快楽MOD の各画面 |
| `F12` | Steam のスクリーンショット既定キー |

`F4` は `Alt+F4` と隣接するため、繰り返し押す用途の既定値には用いない。この占有表は実装側の自動テストで検証する（12.1）。

**areas.json**: `SceneID` 名 → 上記 `[SpawnerTuning]` / `[AdditionalSpawn]` の上書きと `Excluded`（bool）の辞書。未記載エリアはグローバル値。`ExcludedScenes` の既定集合（ボス・イベント・チュートリアル・ギャラリー系 `SceneID`）はプラグインが内蔵し、`Excluded: false` の明示でのみ解除できる。

設定の検証は起動時に行い、`Min > Max`、負値、確率の範囲外、未知の `SceneID` 名・型名・`ItemID` 名、書式不正な `RewardTable` 要素は設定エラーとして提示し、当該項目を既定値へ戻して続行する。`RewardTable` に `Relics` 扱いのアイテムや装備（ワンド等）を指定した場合も設定エラーとし、当該要素を無視する（進行・バランスへの過剰介入の防止）。

## 7. 共存MODとの互換性

### 7.1 破ってはならない前提

- ゲームバイナリ・アセット・セーブデータを書き換えない（SPEC001 のハッシュ照合を壊さない）。
- ゲームの識別子（`EnemyID`、`GalleryEnemyID`、アニメーション、時間尺度）を書き換えない。EDI のトリガー同定は これらに依存する。
- SPEC002 が書き換える難易度の報告値・状態異常系・拘束系のフィールドへ介入しない。本MODの書き換え対象（出現数・間隔・クールタイム・プール上限・位置）と SPEC002 の書き換え対象は互いに素である。
- SPEC003 が参照する快楽・絶頂系の状態へ介入しない。

### 7.2 許容される観測可能な差分

- 敵の数が増える結果、EDI のトリガー発生頻度・拘束機会は増える。これは欠落ではなく増加であり許容する。
- SPEC002 有効時は `Hard` 基準値の上に倍率が乗るため、実効出現数は SPEC002 単独時より多くなる。これは両MODを併用したユーザーの意図どおりである。

### 7.3 起動順序と独立性

本MODは他MODの存在を検出も要求もしない。単独・任意の組み合わせで同一に動作する（有効化条件の独立。DEC-306）。

## 9. エラーと復旧

| 状況 | 挙動 |
|---|---|
| interop シンボル解決の失敗（ゲーム更新等） | 当該機構を無効化し、理由を提示して他機構は継続する。全機構が無効なら実質パススルー。 |

| ギミック複製の例外 | FR-313。当該複製を破棄し、型をセッション中拒否リストへ。 |
| 疑似宝箱の拘束抑止に失敗（例外・抑止点不成立） | 当該個体を当たり扱いとし、バニラの拘束を進行させる（安全側＝バニラ挙動）。連続失敗時は当該エリア滞在中の疑似宝箱を停止する。 |
| 疑似宝箱の非死亡除去が不成立（付録A-11 否定） | FR-322 の縮退: 拘束のみ抑止し個体を残す。報酬は付与する。 |
| 報酬付与（`AddItem`）の例外 | 報酬をスキップしログへ記録する。拘束抑止と個体除去は完了させる。 |
| 停滞計測中のシーン遷移・ゲームオーバー | 計測を破棄し、次エリア入場で初期化。 |

例外はすべて捕捉し、ゲームのメインループへ伝播させない。失敗は常に「介入しない」方向へ倒す。

## 10. 非機能要件

### 10.1 性能

- エリア入場時の一括処理（列挙・書き換え・疑似宝箱の配置）は1フレームで完了し、体感可能なヒッチを生まない。
- 毎フレーム処理は停滞計測（位置サンプリング）と条件監視に限り、追加スポーン判定は `StagnationPenaltyInterval` 等の間隔駆動とする。

### 10.2 安全性

- 全介入はメインスレッド上で行う。
- 上限（FR-308）と除外（FR-311)を介入の入口で検査する。

### 10.3 互換性

- 対象ビルドのハッシュ（冒頭表）と不一致の環境では、起動時に警告を提示する。シンボル解決に成功した機構のみ有効化する。

### 10.4 可観測性

- 介入ログ（FR-319）、設定エラー、縮退の発生をBepInExログへ記録する。
- HUD（5.8）が同じ情報をプレイ中に提示する。ログは事後の証跡、HUDはその場の観測であり、両者は同じ状態を情報源とする。
- 診断JSON（FR-318）は `BepInEx/diagnostics/community.sinisistar2.spawn/` へ出力する。

## 14. 前提、延期事項、残存リスク

### 14.1 明示的な前提

- 対象ビルドは冒頭表のハッシュに一致する。
- スポナーの出現処理はシーンセットアップ後も動的にフィールドを参照する（付録A-2 で確認）。
- ユーザーは追加出現による難所化を許容する。

### 14.2 延期事項

- 追加スポーンの既定値（確率・上限・停滞しきい値）の最終調整。実測とプレイフィールで確定し、確定責任者はバランス調整担当者とする。
- `AllowedGimmickTypes` の既定候補の整備。診断JSONの蓄積後に別途判断する。
- ミミック疑似宝箱の全エリア展開。ミミックプレハブの外部供給（`Ga_Mimic` ギャラリーシーンの一時ロード、またはアセットバンドル参照の保持）が必要で、アセット寿命・メモリ・シーンセットアップ副作用の実測を要する。Phase 1（プール有りエリア限定）の価値確認後に判断する（DEC-312）。
- 疑似宝箱の外れ時に本物の宝箱の開封演出（`ItemGetDialog` 等のUI）を再生する拡張。Phase 1 は在庫加算＋ログ＋MP玉散布で成立させる。
- エリア外の敵種を出現させる拡張（アセットバンドルロード方式）。要望が確定した場合の別仕様とする。
- HUDの出現位置マーカー表示（画面外候補の方角提示）。現在は候補数のみを提示する。
- デバッグ操作のゲームパッド対応。現在はキーボードのみ。

### 14.3 残存リスク

- `EnemyPool.TryGet` の意味論が推論と異なり、追加スポーンが敵の内部状態（`TemporaryEnemySaver` の保存経路等）と干渉する可能性。付録A-1/A-4 の実測で確認し、干渉が確認されたら追加スポーンを縮退する。
- 追加出現がゲームの想定外の負荷・演出競合（同時拘束等)を生む可能性。上限（FR-308）で緩和する。
- 停滞の誤検知（謎解き・鑑賞での停滞へのペナルティ）。しきい値設定で緩和し、既定値は保守的にする。
- `EnmID_Mimic` と実装クラス（候補: `OnlyHoldEnemy`）の対応が推論であり、実測で異なるクラスだった場合は介入点の再特定が必要（付録A-9）。特定できない場合、疑似宝箱は実装しない。
- 本物の宝箱はボタン押下（イベントラベル）で開くのに対し、ミミックは接触で拘束を開始すると推定される。観察力のあるプレイヤーは「触れても掴まれない＝本物」と見分け得る。Phase 1 ではこの差を許容し、疑似宝箱同士（当たり/外れ）の見分け不能性のみを保証する。
- ゲーム更新でシンボル・ハッシュが変わると全機構が停止する（9章の縮退で安全側）。
