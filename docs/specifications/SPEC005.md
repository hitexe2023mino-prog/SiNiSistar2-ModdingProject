## 1. 概要

### 1.1 背景と問題

本来であればシスターおよびプレイヤーとして咎めるべき`堕落（Corruption）`を得る行為に対してメリットを与えることで、敵から性的な攻撃を受けることを「仕方のないこと」として受け入れさせる。徐々に快楽に弱くなり、溺れていく様子をゲームシステム的に再現するためのMODである。プレイヤーに対して、本来であれば避けるべき行為をあえて受け入れさせることで、プレイヤーの行動を誘導し、また堕落の帰結として行動を制限する。

現行仕様（SPEC002/SPEC003 実装済み）では、堕落は罰としてのみ機能する。

- 敵から性的な攻撃（`Sexual`）を受けると堕落が上昇する（SPEC003 FR-218）。
- 堕落が蓄積すると快楽が上昇しやすくなり（SPEC003 FR-209）、絶頂しやすくなって絶頂限界（ゲームオーバー）までの余裕が減る。
- 堕落が閾値に達すると、ゲーム自身の状態異常 `LustMarkCurse` がストック制で付与される（SPEC003 FR-273/FR-274）。ストック1〜3は`淫紋の呪い`であり解呪可能、最終ストック到達で`淫紋`へ**昇華**し、その周回の間は解呪不可となる。
- `LustMarkCurse` 装着中は堕落の獲得量に上方補正が掛かる（SPEC003 FR-267）。ただしこれは**装着中に平坦な倍率を掛ける**という要件行1つだけで定義されており、SPEC003 の制御仕様 5.7「堕落」にも設定表にも記載がない。呪い（可逆）と紋（不可逆）が数値上まったく区別されず、ストック数にも連動しない。本仕様 5.5 はこの不備を段階化された係数として解消する。
- 装着中は SPEC002 の快楽系状態異常集合に含まれるため、拘束中の抵抗入力が無力化窓で拒否され得る（SPEC002 5.3）。

罰しかない軸では、プレイヤーは堕落を避け続けるだけであり、「受け入れてしまう」動機がシステム上に存在しない。本仕様は、堕落しきったアクターに限定した回復手段（淫魔化バフ）と、それと対になる新たなペナルティ（MP枯渇時の確率硬直）を追加し、性行為を能動的に受け入れなければならない状況をゲームシステムとして再現する。

### 1.2 目的

- 淫紋へ昇華済みのアクターが絶頂したとき、HPとMPがゆっくりと回復する`淫魔化バフ`を与える。連続して絶頂した場合は効果時間を加算延長する。
- バフは絶頂時に限定する。絶頂は絶頂回数を1消費して絶頂限界（SPEC003 5.5）へ近づく行為であり、プレイヤーは無償ではなくリスクと引き換えにバフを得る。
- 淫紋（昇華後）の効果中、性的攻撃による快楽の上昇量に固定の上方補正（既定1.25倍）を掛ける（新規実装。「身体が敏感になる」フレーバーの数値化）。
- 堕落の蓄積速度を淫紋の段階で変える。呪いなしは影響なし、呪いストック数に応じて軽微に加速、昇華（淫紋）で大幅に加速する。可逆な警告段階と不可逆な確定段階の差を、蓄積速度の不連続な崖として表す。
- 淫紋が付与され、かつ堕落が閾値以上のアクターがMP0のまま行動すると、予測不能なタイミングで硬直が発生するペナルティを与える。これにより、十分に堕落したプレイヤーは敵との性行為を積極的に受けてMPを回復させなくてはならない。
- 堕落による`淫紋の呪い`と`淫紋`の進行時に、絶頂時と類似のピンクの靄の画面演出を行う。靄の濃度・規模は段階レベルに応じる。
- 調整値をBepInEx設定で変更可能にし、ゲームのセーブデータを書き換えない。全機構を無効化すれば挙動がMOD導入前（SPEC003 現行版）と一致する。
- SPEC001/002/004 と同一ゲームルートで共存する。

### 1.3 成功条件

1. 淫紋へ昇華済みの状態で絶頂すると、以後一定時間、HPとMPが設定量でゆっくり回復する。昇華していない状態の絶頂では回復しない。
2. バフ有効中に再度絶頂すると、残り効果時間が加算される（既定で上限なし）。
3. セーブポイントをインタラクトすると、バフの残り効果時間が破棄され、回復が止まる。
4. 絶頂限界へ到達する絶頂（致死化が成立する絶頂）ではバフが発動せず、ゲームオーバーが SPEC003 のとおり成立する。
5. 淫紋へ昇華済みの状態では、同一の性的被弾・同一の堕落値での快楽上昇量が昇華前の1.25倍（既定）である。昇華前は呪いを装着していても倍率が掛からない。
6. 同一の性的被弾に対する堕落の増加量が、呪いなし＜呪いストック（数に応じて増加）＜昇華済み の順に大きい。昇華済みの増加量は、最終可逆ストックの増加量より不連続に大きい。
7. 淫紋が付与され、堕落が閾値以上で、MPが0のとき、対象の行動入力に対して確率で硬直モーションが発生する。条件のいずれか1つでも欠けると発生しない。イベント再生中・拘束中・敗北演出中・時間停止中は発生しない。
8. `淫紋の呪い`のストック増加時と昇華の成立時に、ピンクの靄の演出が段階に応じた濃度で表示される。
9. 全機構を無効化した設定、またはMOD（本仕様分の機構）を取り外した状態で、ゲームの挙動が SPEC003 現行版と一致する。セーブデータと随伴ファイルに本仕様由来の差分が残らない。
10. SPEC001/002/004 が同時に動作している状態で、いずれの動作も停止しない。

## 2. スコープ

### 2.1 対象

- 淫魔化バフ：昇華後の絶頂を契機とするHP/MPの緩速回復と、加算型の効果時間管理（5.1）。
- 淫紋（昇華後）の快楽上昇補正（5.2）。
- 堕落の蓄積速度の段階化。SPEC003 FR-267 の平坦な倍率の適用規則を置き換える（5.5）。
- MP0ペナルティ：入力起点の確率硬直（5.3）。
- 呪い・紋の進行演出：ピンクの靄の段階表示（5.4）。
- BepInEx `ConfigEntry` による調整値の追加（SPEC003 と同一の設定ファイル）。
- 全機構の無効化と巻き戻し。

### 2.2 非対象

- SPEC003 の既存機構（絶頂の定義、絶頂限界と致死化、淫紋ストック制、サイドカー永続化）の変更。堕落については、単調非減少・上限・基準増加量（`CorruptionPerClimax` / `CorruptionPerSexualHit`）・快楽への作用（FR-209）を変更しない。変更するのは FR-267 の倍率の適用規則だけである（5.5）。
- サイドカーのスキーマ変更。淫魔化バフは永続化しない（DEC-409）。
- ゲームのMP消費仕様、魔法攻撃の仕様、バニラのMP0魔法硬直（MP0で魔法攻撃を行った際の既存の硬直）の変更（DEC-406）。
- 新規モーション・アニメーション資産の作成。硬直はゲーム既存のモーションの流用に限る。
- 堕落を減少させるいかなる経路（SPEC003 FR-219 の維持）。
- 敵側への一切の介入。本仕様の全機構はプレイヤーにのみ作用する。
- `GameAssembly.dll`、`global-metadata.dat`、ゲームアセット、セーブデータファイルの書き換え。
- 快楽値を条件とする硬直発生（原ドラフト検討事項。5.3へ統合し不採用。DEC-407）。

### 2.3 前提と制約

- 本仕様が参照する堕落・絶頂・淫紋ストックは `community.sinisistar2.pleasure` プラグインの内部状態であり、各MODは相互依存を宣言できない（SPEC003 FR-227）。したがって本仕様を別プラグインとして実装することはできない（DEC-401）。
- 絶頂の成立、昇華の成立、ストック数の変化は、同一プラグイン内のイベントとして観測できる。ゲーム側への新たな観測点は不要である。
- HPの回復はゲーム自身の `PlayerStatusManager.HP.Recover(int, bool)` で行える（SPEC003 2.3）。MPも同じ基底クラス（`BattleMainParameter`）を持ち、`PlayerStatusManager.MP.Recover(int, bool)` で回復できる（A-402、interopメタデータで確認済み）。
- 「MP0で魔法攻撃を行うと極短時間の硬直が発生する」は現行ゲームの既存挙動である。この硬直は魔法アクション（剣魔法）自身が持つ「空撃ち」分岐（`AnimState.Magic_Sword1_Empty`）であり、MODはアニメーターへ直接介入せず、ゲーム自身の入力受付（`Pressed()`/`PressedThisFrame()`）へ押下を渡すことで、ゲームにMP不足を判定させて空撃ちを発生させる（A-401、ISIL解析で確認）。
- ピンクの靄の描画は SPEC003 の絶頂演出（FR-268）が既に持つ描画系を流用できる。ゲームの演出資産を使用せず、`Time.timeScale` を変更しない制約（SPEC003 FR-212）は本仕様にも適用される。
- 対象ビルドの IL2CPP ネイティブ実装は interop アセンブリから読めないが、BepInEx 同梱の Cpp2IL により ISIL として読める。実測の前段調査に用いてよい。

## 3. 用語

SPEC003 の用語（快楽、絶頂、絶頂回数、絶頂限界、堕落、致死化、随伴ファイル）をそのまま用いる。本仕様の追加用語は次のとおり。

| 用語 | 定義 |
|---|---|
| 昇華済み | その周回で `LustMarkCurse` が最終ストックへ到達済みであること（SPEC003 FR-273）。以後その周回の間は真であり続ける。 |
| 装着中 | プレイヤーに `LustMarkCurse` が1ストック以上有効であること。付与経路（堕落由来・敵の攻撃由来）を問わず、昇華の前後も問わない。本仕様では5.3のMP0ペナルティの条件としてのみ用いる（5.2の快楽補正は昇華済みを条件とする）。 |
| 淫魔化バフ | 昇華済みのプレイヤーが絶頂したときに発動する、HPとMPの緩速回復効果。 |
| 残り効果時間 | 淫魔化バフが継続する残り秒数。絶頂ごとに加算される。 |
| MP0ペナルティ | 5.3の条件下で、行動入力に対して確率で硬直を発生させる機構。 |
| 対象入力 | MP0ペナルティの抽選契機となる行動入力の集合。設定 `StunTriggerInputs` が定める。 |
| 硬直流用 | ゲームが持つMP0魔法攻撃時の硬直モーションを、MODが別の契機で再生させること。 |
| 進行演出 | 呪いストックの増加または昇華の成立を契機とするピンクの靄の画面演出。 |
| 段階レベル | 進行演出の濃度を決める段。現在のストック数を用い、昇華を最上位段とする。 |

## 4. 採用設計

### 4.1 全体構成

本仕様の機構はすべて SPEC003 のプラグイン内へ追加する。

```
community.sinisistar2.pleasure（SPEC003 + 本仕様）
  ├ PleasurePlugin (BasePlugin)          既存。設定読込へ本仕様のキーを追加
  ├ Harmonyパッチ群                      既存 + 入力観測・硬直再生の介入点
  ├ PleasureOverlay (MonoBehaviour)      既存。進行演出の靄描画を追加
  └ SiNiSistar2.Pleasure.Core            純粋ロジック（ゲーム参照なし・単体テスト対象）
      ├ （既存: PleasureMeter, ClimaxLedger, CorruptionTrack, …）
      ├ RegenBuffTrack                   バフの発動判定、残り時間の加算・消費、回復量の割当
      ├ MpZeroStunScheduler              ペナルティ条件判定、入力抽選、クールダウン
      └ CrestProgressEffect              進行演出の段階と濃度の決定
```

窓・時間・確率の決定はすべて `Core` に置き、時刻と乱数を注入して単体テストで検証する。`Plugin` はゲームの値を読み、`Core` へ渡し、返った決定を適用するだけの層とする（SPEC001〜004 と同じ構成）。

### 4.2 バフとペナルティの対

```
堕落の進行                    プレイヤーへの意味
────────────────────────────────────────────────
呪いストック 1〜3   ──→ 警告。解呪可能。進行演出（靄・弱）
        │                堕落の蓄積が軽微に加速（新規 5.5、ストック数に比例）
        │                └─ まだ引き返せる。解呪すれば加速は止まる
        ▼    ← ここに崖がある（蓄積係数が不連続に跳ね上がる）
昇華（淫紋）        ──→ 解呪不可。進行演出（靄・最大）
        │                堕落の蓄積が大幅に加速（新規 5.5）
        │                昇華後: 快楽上昇の固定上方補正（新規 5.2、既定1.25倍）
        │                絶頂 ──→ 淫魔化バフ（HP/MP緩速回復、加算延長）
        │                              ↑ ただし絶頂回数を1消費（絶頂限界へ近づく）
        ▼
装着 AND 堕落≥閾値 AND MP0
                    ──→ 行動入力に確率硬直（MP0ペナルティ）
                          └─ MPを回復するには絶頂（＝性行為の受け入れ）が最短
```

バフとペナルティは循環を構成する。MPが尽きたプレイヤーは硬直の危険に晒され、それを解消する安定手段が「敵の性的攻撃を受けて絶頂する」ことである。絶頂は絶頂限界を消費するため、受け入れには常に代償が伴う。

### 4.3 代替案とトレードオフ

| 論点 | 採用 | 採用しなかった案 | 理由 |
|---|---|---|---|
| 実装先 | SPEC003 プラグインの拡張 | 新規プラグイン（`community.sinisistar2.corruption` 等） | 堕落・絶頂・淫紋ストックはプラグイン内部状態であり、MOD間依存の禁止（SPEC003 FR-227）の下で外部から読めない（DEC-401） |
| バフの発動契機 | 昇華後の絶頂のみ | 昇華の瞬間にも発動 | 「残機（絶頂回数）を消費して得る」という原意のリスク設計に反する。昇華は堕落の蓄積だけで到達し得る（DEC-402） |
| 同上 | 昇華後の絶頂のみ | 昇華後の常時パッシブ回復 | 原ドラフトが「絶頂時に限定することで無償でバフを得るのではなくリスクを与える」と明示している |
| 効果時間 | 加算型・上限なし（既定） | リセット型／加算型・上限あり | 利用者決定（2026-08-10）。連続絶頂の「貯め」を許す。上限は設定 `RegenDurationCap` で任意に課せる形で残す（DEC-403） |
| 硬直の契機 | 行動入力の押下を起点に確率発生 | 入力と無関係な時間経過での発生 | 利用者決定（2026-08-10）。入力と無関係に再生するとイベントシーン中などに硬直が再生されて進行を壊すリスクがある（DEC-404） |
| 同上 | 入力起点 | 変更なし（既存挙動の再解釈のみ） | 機構が存在しなければ「予測不能なタイミングの硬直」は成立しない |
| ペナルティの適用条件 | 装着中 AND 堕落≥閾値 | MP0なら常時／昇華後のみ | 利用者決定（2026-08-10）。まだ十分に堕落していないが淫紋（呪い）は敵に付与されているシナリオが存在するため、装着だけでは発火させない（DEC-405） |
| 魔法攻撃の抽選対象化 | 既定で対象外 | 対象に含める | バニラがMP0の魔法攻撃を既に毎回硬直させるため、抽選は無意味か二重発生になる。バニラ挙動は変更せず、対象入力は設定で変更可能とする（DEC-406） |
| 快楽補正の適用条件 | 昇華後のみ・固定倍率（既定1.25） | 装着中（ストック1以上）に適用、ストック数・堕落連動の倍率 | **利用者決定（2026-08-10）**。快楽の上昇量は既に堕落係数（SPEC003 FR-209）で堕落の進行度を参照しており、堕落・段階と連動する補正を重ねると同じ軸の二重管理になる（DEC-408） |
| バフの永続化 | しない（セッション限定） | サイドカーへ保存 | 快楽を保存しないのと同じ理由（SPEC003 4.3）。ロード直後に回復状態を持ち越す意味がなく、スキーマ変更を避ける（DEC-409） |
| 進行演出の描画 | 絶頂演出（FR-268）の靄描画系を流用 | 独自描画の新設 | 同一プラグイン内に実績のある描画系が既にあり、視覚言語（ピンクの靄＝性的な状態変化）も一貫する（DEC-411） |

## 5. 制御仕様

### 5.1 淫魔化バフ

**発動条件**（すべて満たすこと）

1. 昇華済みである（その周回で `LustMarkCurse` が最終ストックへ到達済み）。
2. 絶頂が成立した（SPEC003 FR-211 の状態変化が起きた）。
3. その絶頂で致死化（SPEC003 FR-215）が成立しない。致死化する絶頂ではバフを発動しない。

昇華の成立そのものはバフを発動しない。昇華前の絶頂もバフを発動しない。

**効果時間**

- 発動ごとに残り効果時間へ `RegenDurationPerClimax` 秒を加算する。
- `RegenDurationCap` が `0` より大きい場合、残り効果時間はその値で頭打ちとする。`0`（既定）の場合、上限を設けない。
- 残り効果時間は通常プレイ中にのみ消費する。イベント再生中・敗北演出中・`Time.timeScale` が `0` の間は消費せず、回復も行わない。拘束中は消費・回復ともに継続する。
- `LeliaDeadState` が `Live` でない間は回復も消費も行わない。ゲームオーバーが成立した時点で残り効果時間を破棄する。
- スロット読込・新規ゲーム開始・シーン遷移をまたぐ保存は行わない。スロット読込と新規ゲーム開始で残り効果時間を破棄する。
- セーブポイントのインタラクト（SPEC003 FR-217 と同じ検出点 `SavePointAsyncLabel.ExecutionOneAsync`）で残り効果時間を破棄する。破棄は `ResetAtObeliskOnly` の値にかかわらず行う（絶頂回数がリセットされないインタラクトでも、バフは破棄する）。

**回復**

- バフ有効中、HPを毎秒 `HpRegenPerSecond`、MPを毎秒 `MpRegenPerSecond` の割合で回復する。
- 回復はゲーム自身の操作で行う。HPは `HP.Recover`、MPは `MP.Recover` を用いる（A-402）。実行時に対象APIが機能しないと判明した場合はMP回復のみ停止し、理由を記録する（9章）。
- 回復量は `Core` 側で実数として累積し、1以上に達した整数分だけをゲームへ渡す。端数を切り捨てて失わない。
- 回復は各パラメータの最大値を超えない。超過分は捨てる。
- MODはHP/MPの現在値を自算して直接書き込まない（SPEC003 FR-275 と同じ原則）。

### 5.2 淫紋（昇華後）の快楽上昇補正

- プレイヤーが昇華済みである間、性的被弾による快楽の上昇量へ `CrestPleasureGainScale` を乗じる。既定は `1.25`（利用者指定 2026-08-10）。
- 補正は昇華済みか否かだけで決まる**固定倍率**とする。堕落の進行度、ストック数、レベルに連動させない。快楽の上昇量は既に堕落の進行度を参照している（SPEC003 FR-209 の堕落係数）ため、堕落と連動する補正を二重に掛けない（DEC-408）。
- 昇華前（呪いストック1〜3の装着中）には掛けない。呪い段階の敏感化は堕落係数が既に表現している。
- `CrestPleasureGainScale` は `1` 未満を許さない（淫紋が快楽への耐性になってはならない）。`1` で無変更。

#### 5.2.1 快楽上昇量の合成式

1回の性的被弾による快楽の上昇量は次で求める。SPEC003 FR-209 の式へ淫紋係数を1つ乗じたものであり、他の項を変更しない。

```
快楽上昇量 = PleasureGainPerHit
             × (1 + 堕落 × CorruptionGainScale)      ← 堕落係数（SPEC003 FR-209。既存）
             × 淫紋係数                                ← 本仕様（5.2）

淫紋係数 = 昇華済み        → CrestPleasureGainScale（既定 1.25）
           昇華前（呪い含む） → 1.0
```

| 記号 | 出所 | 備考 |
|---|---|---|
| `PleasureGainPerHit` | SPEC003 6章の設定 | 被弾1件あたりの基準上昇量 |
| `堕落` | SPEC003 の堕落（`0`〜`CorruptionCap`） | 単調非減少。淫紋の有無と独立に進行する |
| `CorruptionGainScale` | SPEC003 6章の設定 | 堕落の進行を快楽へ反映する唯一の係数 |
| `CrestPleasureGainScale` | 本仕様 6章の設定（既定 `1.25`、`1` 未満不可） | 昇華済みか否かだけで決まる固定値 |

進行の度合いは堕落係数の項だけが担い、淫紋係数は状態の有無で `1.0` か `1.25` を取る二値である。淫紋係数をストック数やレベルへ連動させてはならない（DEC-408）。

例（`PleasureGainPerHit` = 0.10、`CorruptionGainScale` = 1.0、堕落 = 0.40 のとき）:

| 状態 | 堕落係数 | 淫紋係数 | 上昇量 |
|---|---|---|---|
| 呪いなし | 1.40 | 1.00 | 0.140 |
| 呪いストック1〜3（昇華前） | 1.40 | 1.00 | 0.140 |
| 昇華済み（淫紋） | 1.40 | 1.25 | 0.175 |

昇華前の2行が同値であることは意図した結果である。呪い段階での「敏感になっていく」進行は、堕落そのものが増えることで既に表現されている。

この表は淫紋係数の効果を切り分けるため**堕落を 0.40 に固定**している。実プレイでは呪いストックが増えるほど堕落の蓄積自体が速くなる（5.5）ため、同じ時間を過ごしたときの堕落値は段階ごとに異なり、快楽の上昇量も段階に応じて開いていく。段階間の差は堕落係数の項を通して現れる。

### 5.3 MP0ペナルティ

**適用条件**（すべて満たすこと。1つでも欠ければ抽選しない）

1. プレイヤーが `LustMarkCurse` を装着している。
2. 堕落が `MpPenaltyCorruptionFraction`（`CorruptionCap` に対する割合）以上である。**既定は `1.0`、すなわち堕落が上限に達していること**（利用者決定 2026-08-10）。自分の手足が信用できなくなることは堕落が為す最も深い事であり、紋が現れる地点ではなく軌道の底に置く。
3. プレイヤーのMPが `MpPenaltyMpFraction`（最大値に対する割合）を**下回る**。**既定は `0.2`、すなわちMPが2割を切っていること**（利用者決定 2026-08-10）。`0` は「空のときだけ」という旧解釈に戻す。MPが読めない場合は条件不成立とする（誰も確認していない状態で発火させない）。
4. 通常プレイ中である。イベント再生中・ギャラリー再生中・拘束中・敗北演出中・`Time.timeScale` が `0` の間は適用しない。
5. `LeliaDeadState` が `Live` である。

条件1と2はAND条件である。敵の攻撃で淫紋だけが付与された低堕落の状態では発火しない（DEC-405）。

**抽選と発生**

- 契機は対象入力の**押下開始（エッジ）のみ**とする。押しっぱなしの間の毎フレーム抽選、時間経過による抽選を行わない。
- 対象入力は設定 `StunTriggerInputs` が定める。既定は通常攻撃・ジャンプ・移動開始とし、魔法攻撃を含めない（バニラがMP0の魔法攻撃を既に毎回硬直させるため。DEC-406）。
- 押下1回につき確率 `StunChance` で硬直を発生させる。
- 硬直が発生したら、以後 `StunCooldownSeconds` の間は抽選しない。連続入力による硬直の連鎖（スタンロック）を作らない。
- 硬直はゲームが持つMP0魔法攻撃時の硬直モーションを流用して再生する。新規モーションを作らず、存在しない take 名を作らない（SPEC001 のトリガー同定の保護。SPEC003 FR-228 と同じ制約）。再生は剣魔法アクションの `Pressed()`/`PressedThisFrame()` を呼び、MP不足の判定と空撃ちモーションの選択はゲーム自身に委ねる（A-401解決済み）。プレイヤーが実際に魔法を試みたことになるため、FR-228の制約と矛盾しない。
- バニラのMP0魔法硬直そのものは変更しない。同一の入力に対して硬直を二重に発生させない。

### 5.4 進行演出

- 契機は次の2つである。(a) `LustMarkCurse` のストック数が増加した。(b) 昇華が成立した。
- 演出は絶頂演出（SPEC003 FR-268）と類似のピンクの靄とし、同じ描画系を流用する。ゲームの演出資産を使用せず、`Time.timeScale` を変更せず、カメラを変位させない。
- 靄の濃度と規模は段階レベルに応じて増す。段階レベルは発生時点のストック数とし、昇華を最上位段とする。
- 演出は一過性とし、`CrestFxDurationSeconds` で消える。堕落HUD（SPEC003 FR-266 の紋の可視化）とは独立である。
- 演出が描画できない場合でも、ストックの増加・昇華の状態変化を妨げない（SPEC003 FR-213 と同じ思想）。
- SPEC003 FR-274 の除外窓（イベント再生中・拘束中・敗北演出中・時間停止中）でストックの付け直しが保留された場合、演出も保留し、付与の成立時に1回だけ再生する。

### 5.5 堕落の蓄積速度の段階化

`淫紋の呪い`は解呪可能な警告段階であり、`淫紋`は解呪不可な確定段階である（SPEC003 FR-273）。両者は「まだ引き返せる段階」と「取り返しのつかない結果」の関係にあり、堕落の蓄積速度はこの差を反映しなければならない。

SPEC003 FR-267 は装着中に平坦な倍率 `CorruptionCrestGainScale` を掛けると定めるのみで、呪いと紋を区別せず、ストック数にも連動しない。本節はこれを段階化された係数へ改める（DEC-413）。本節は SPEC003 FR-267 の倍率の適用規則を**置き換える**。

#### 5.5.1 合成式

堕落の増加は、SPEC003 5.7 の基準増加量へ淫紋蓄積係数を乗じて求める。

```
堕落増加量 = 基準増加量 × 淫紋蓄積係数

  基準増加量 = 絶頂時       → CorruptionPerClimax      （SPEC003 5.7。変更しない）
               性的被弾時   → CorruptionPerSexualHit   （SPEC003 5.7。変更しない）

  淫紋蓄積係数 = 呪いなし              → 1.0
                 呪いストック n（可逆） → 1 + CorruptionCurseGainMax × n / (M - 1)
                 昇華済み（淫紋）        → CorruptionCrestGainScale
```

`M` は最終ストック数であり、ゲームから読む（`AbnormalData.MaxLevel`。SPEC003 FR-273）。可逆段階は `n = 1 … M-1` であり、`n = M` への到達が昇華である。

- `M ≤ 1` の場合、可逆段階が存在しない。ストック項を適用せず、1ストック目の付与がそのまま昇華として扱われる。
- 昇華済みの係数はストック項を**加算しない。置き換える**。昇華後も最終ストックを保持しているため、加算にすると連続な値になり、崖が消える。
- 係数は堕落そのものの値に連動させない。堕落の進行に応じた加速は、堕落が増えること自体が既に表している。

#### 5.5.2 段階と係数

`M = 4`、`CorruptionCurseGainMax` = `0.30`、`CorruptionCrestGainScale` = `2.0` を仮に置いた場合（いずれも暫定案。確定は付録A A-406）:

| 段階 | 可逆性 | 淫紋蓄積係数 | 意味 |
|---|---|---|---|
| 呪いなし | — | `1.00` | 蓄積速度に影響を与えない |
| 呪いストック1 | 解呪可 | `1.10` | 軽微 |
| 呪いストック2 | 解呪可 | `1.20` | 軽微 |
| ストック3（最終手前） | 解呪可 | `1.30` | 軽微の上限 |
| **昇華（淫紋）** | **解呪不可** | **`2.00`** | **大幅。崖** |

呪い段階の上限（`1 + CorruptionCurseGainMax`）と昇華の係数の間に不連続な差を置くことが本節の要点である。呪い段階の加速は「急げば間に合う」範囲に留め、昇華の瞬間に蓄積速度が跳ね上がることで、取り返しのつかなさを数値として成立させる。

#### 5.5.3 検証規則

- `CorruptionCrestGainScale` は `1 + CorruptionCurseGainMax` 以上でなければならない。`CorruptionCurseGainMax` が正のときは真に大きくなければならない（崖が存在しない構成を許さない）。
- 両者とも `1` 未満（`CorruptionCurseGainMax` は負）を許さない。淫紋が堕落への耐性になってはならない。
- 違反した場合は設定エラーとして提示し、段階化を無効化して係数 `1.0` で動作する。堕落の蓄積そのものは止めない。

#### 5.5.4 他の軸との関係

段階が影響する先を1本に絞り、同じ軸を二重に管理しない（DEC-408、DEC-413）。

| 影響元 | 影響先 | 定義 |
|---|---|---|
| 淫紋の**段階**（ストック数・昇華） | 堕落の蓄積速度 | 本節 5.5 |
| 堕落の**値** | 快楽の上昇量 | SPEC003 FR-209（唯一の連続的な進行表現） |
| 淫紋の**有無**（昇華済みか） | 快楽の上昇量に固定係数 | 5.2（二値。段階に連動しない） |

段階は堕落を経由して快楽へ届く。段階から快楽への直接の連続的な経路は 5.2 の二値係数だけであり、進行の度合いを2箇所で持たない。

「実測後に確定」の既定値は、実測前はすべて挙動不変相当（時間0、確率0）とし、未検証の値でゲームを壊さないようにする（SPEC002/003 と同じ規約）。

例外は `CrestPleasureGainScale`（`1.25`）、`RegenDurationPerClimax`（`15`）、`HpRegenPerSecond` / `MpRegenPerSecond`（各 `2`）、`MpPenaltyCorruptionFraction`（`1.0`）、`StunChance`（`0.2`）である。いずれも実測を要する調整値ではなく利用者が指定した確定値であり、本仕様分を導入した時点から作用する（淫魔化バフは昇華済みかつ絶頂を経た初回から、MP0ペナルティは条件成立の初回から）。したがって「導入しただけでは挙動が変わらない」はこれらの値には当てはまらない。無変更に戻すには、それぞれ `1.0`／`0`／`0`／`0`（バフを恒久的に外すには `Regen.Enabled=false`）／`0`（ペナルティを外すには `MpPenalty.Enabled=false`）を設定する。

**設定の検証**（SPEC003 6.2 に準じる）

- 負の値、および `CrestPleasureGainScale < 1` は設定エラーとして提示し、当該機構を無効化する。
- 5.5.3 の検証規則（崖の存在、`1` 未満の禁止）に違反した場合は設定エラーとして提示し、堕落の段階化を無効化する（係数 `1.0`）。堕落の蓄積そのものは止めない。
- `StunTriggerInputs` の未知の入力名は無視し、無視した名前を提示する。集合全体を無効化しない。

## 9. エラーと復旧

## 10. 非機能要件

- 抽選は入力のエッジ検出時のみ動く。条件不成立（非装着、堕落不足、MP>0）の場合は最短で復帰し、毎フレームの走査を行わない。
- バフの回復適用は `RegenTick`（1秒未満の固定間隔）単位とし、毎フレームのHP/MP書き込みを行わない。
- 演出はオーバーレイ描画に限り、ゲームのUI階層・Canvas へ介入しない。
- すべての介入はメインスレッド上で完結し、フレーム処理を待機で停止させない。

## 12. 設計判断

| ID | 判断 | 理由 | 採用しなかった案 |
|---|---|---|---|
| DEC-401 | SPEC003 プラグイン内へ実装する | 堕落・絶頂・淫紋ストックはプラグイン内部状態であり、MOD間依存禁止の下で外部から読めない | 新規プラグイン |
| DEC-402 | バフの契機は昇華後の絶頂のみ | 絶頂回数の消費というリスクと対にする原意。昇華は蓄積だけで到達し得る | 昇華時発動、常時パッシブ |
| DEC-403 | 効果時間は加算型・上限なし（既定） | **利用者決定（2026-08-10）**。上限は `RegenDurationCap` で任意に課せる | リセット型、上限あり |
| DEC-404 | 硬直は行動入力の押下を起点に確率発生 | **利用者決定（2026-08-10）**。入力と無関係な再生はイベントシーン中に壊れるリスクがある | 時間経過での発生、変更なし |
| DEC-405 | ペナルティは装着 AND 堕落が上限（既定 `1.0`） | **利用者決定（2026-08-10）**。敵の攻撃で淫紋だけが付与された低堕落シナリオでは発火させない。閾値は当初 `CorruptionCrestAtFraction`（0.5）と同値を推奨したが、利用者が上限（100%）へ確定した。自分の手足が信用できなくなることは堕落が為す最も深い事であり、紋が現れる地点ではなく軌道の底に属する。0.5 では紋が付いた時点で発火し、まだ半分残っている転落の全体が平坦になる | MP0なら常時、昇華後のみ、閾値0.5 |
| DEC-406 | 魔法攻撃を抽選対象の既定から外し、バニラのMP0魔法硬直を変更しない | バニラが既に毎回硬直させるため、抽選は無意味か二重発生になる | 魔法攻撃も抽選対象に含める |
| DEC-407 | 快楽値を条件とする硬直拡張（原ドラフト検討事項）を採用しない | 通常攻撃は対象入力の既定に含まれており、快楽ゲートの追加は条件の二重化になる | 快楽閾値ゲート付きのX攻撃硬直 |
| DEC-408 | 快楽補正は昇華（淫紋）後のみ、固定倍率1.25で適用する | **利用者決定（2026-08-10）**。快楽の上昇量は既に堕落係数（SPEC003 FR-209）で堕落の進行度を参照している。呪い段階・堕落量・ストック数に連動する補正を重ねると、同じ「敏感になっていく」軸を2箇所で管理することになり、二重管理のリスクを生む。淫紋の補正は状態の有無だけで決まる固定倍率とし、進行の表現は堕落係数へ一本化する | 装着中（ストック1以上）適用、ストック数・堕落連動の倍率 |
| DEC-409 | バフを永続化しない | 快楽を保存しない SPEC003 4.3 と同じ理由。サイドカーのスキーマ変更を避ける | サイドカー保存 |
| DEC-410 | 致死化する絶頂ではバフを発動しない | 死亡の瞬間に回復が走る競合を作らない | 発動後に破棄 |
| DEC-411 | 進行演出は絶頂演出の靄描画系を流用する | 同一プラグインに実績があり、視覚言語が一貫する | 独自描画の新設 |
| DEC-413 | 堕落の蓄積速度を淫紋の段階で変える（呪いなし=1.0、可逆ストックは数に応じて軽微、昇華で不連続に大幅） | **利用者REVIEW（2026-08-10）**。呪いと紋は「まだ引き返せる段階」と「取り返しのつかない結果」の関係にあり、平坦な倍率ではその差が数値に現れない。呪い段階の加速を軽微に留めることで警告として機能させ、昇華の瞬間の崖によって不可逆性を体感させる。段階が影響する先は堕落だけに限り、快楽へは堕落を経由して届く（5.5.4） | SPEC003 FR-267 の平坦な倍率（装着中に一律）、堕落の値に連動する連続的な係数 |
| DEC-412 | セーブポイントのインタラクトでバフを破棄する | **利用者決定（2026-08-10）**。セーブポイントは休息の節目であり火照りはそこで冷める。絶頂回数のリセットとバフの破棄が常に同時になるため、リセットを繰り返して効果時間だけを持ち越す蓄積が成立しなくなる。破棄は `ResetAtObeliskOnly` に依存させず、回数リセットの有無より広く適用する | 絶頂回数リセット時のみ破棄、破棄しない（改訂前） |

## 14. 前提・延期事項・リスク

### 14.1 承認済みの前提

- 加算型・上限なしの効果時間（利用者決定）。
- 入力起点の確率硬直（利用者決定）。
- 装着 AND 堕落閾値のペナルティ条件（利用者決定）。
- セーブポイントのインタラクトでのバフ破棄（利用者決定）。

### 14.2 延期事項

- 調整値の実数（回復量、効果時間、確率、閾値、演出濃度）— 付録Aの実測後に確定。
- ~~MPの回復経路の確定（A-402）~~ 解決済み（`MP.Recover`、interopメタデータで確認）。
- ~~硬直モーションの再生経路の確定（A-401）~~ 解決済み（剣魔法アクションの空撃ち分岐、ISIL解析で確認）。

### 14.3 残存リスクと軽減策

| リスク | 影響 | 軽減策 |
|---|---|---|
| セーブポイントを避けたまま絶頂を重ね、効果時間を長時間積み上げる運用（加算・上限なしのため） | 一時的な高回復状態の長期化 | 絶頂回数は限界へ単調に近づき、リセットにはセーブポイントのインタラクトが必要で、その時点でバフは破棄される（FR-407、DEC-412）。恒久化は成立しない。さらに絞る場合は `RegenDurationCap` を課す |
| 硬直流用の再生経路が見つからない | MP0ペナルティが成立せず、バフとの循環（4.2）が片輪になる | 確定まで既定無効（FR-411）。経路がない場合は仕様の縮退として記録し、代替（移動速度低下等）は別途変更提案とする |
| MP回復経路が見つからない | 「MPを絶頂で回復する」動機付けが成立しない | 確定まで無効（FR-405）。HP回復のみでもバフとしては成立する |
| 昇華後の快楽補正（既定1.25）は導入時点から挙動を変える唯一の確定値である | 昇華後の絶頂間隔が想定より短くなる可能性 | 利用者指定値のため既定とする。バランス調整は `CrestPleasureGainScale` の変更のみで可逆 |
| **堕落の正のフィードバックループ**：堕落が増える → 要求ストックが増える（SPEC003 FR-274） → 蓄積係数が上がる → さらに堕落が増える。昇華後は係数が最大で固定されるため発散はしないが、呪い段階の通過が想定より速くなり、警告としての猶予が失われ得る | 「引き返せる段階」が実質的に存在しなくなる | ループの利得は `CorruptionCurseGainMax` が直接決める。呪い段階を軽微（暫定案 最大でも +0.30）に抑えることが、猶予を残すための設計上の要である。実測 A-406 では「呪いを受けてから昇華までに解呪が間に合うか」を判定基準とする |
| 昇華後は蓄積係数が最大で張り付き、堕落は `CorruptionCap` へ急速に到達する | 昇華後の堕落の進行が計器として機能しなくなる（すぐ天井） | 上限到達後も絶頂回数と絶頂限界が敗北の計器として機能する（SPEC003 5.5）。`CorruptionCap` と `CorruptionCrestGainScale` の比で到達時間を調整する |
